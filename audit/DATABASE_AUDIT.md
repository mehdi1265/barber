# DATABASE AUDIT — Barber App

> **Question answered:** what data model exists (local and cloud), how do the two schemas differ, which guarantees are missing, and which defects threaten data integrity?
> **Sources:** `src/database/migrations/001_initial.sql` (216 lines), `supabase/migrations/001_initial_schema.sql` (289 lines), `src/database/sqlite/{database,migrations}.ts`, all repositories, `docs/06-database-api-design.md`.
> **Nothing in this document was applied to a database.** All statements are static analysis.

---

## 1. Local schema (SQLite) — 13 application tables + 1 runner table

Timestamps are ISO-8601 **UTC strings** in `TEXT`. Money is `INTEGER` **Toman × 100**. IDs are RFC-4122 UUID strings generated by the client. Soft delete uses `deleted_at` where present.

| # | Table | Purpose | Key columns | Indexes | Notes |
|---|---|---|---|---|---|
| 1 | `profiles` | Owner profile | `id` PK, `user_id` UNIQUE, `display_name`, `phone`, `currency_code` | `user_id` | One row per owner; `id` is set to `user_id` at registration |
| 2 | `customers` | Customer directory | `id`, `user_id`, `name`, `phone`, `notes`, `deleted_at` | `user_id`, `(user_id,name)`, `(user_id,phone)` | Soft delete |
| 3 | `services` | Service catalog | `id`, `user_id`, `name`, `default_price`, `suggested_duration_minutes`, `is_active` | `user_id` | `is_active IN (0,1)` |
| 4 | `appointments` | Bookings | `id`, `user_id`, `customer_id`→customers, `title`, `start_at`, `duration_minutes`, `end_at`, `status`, `notes`, `deleted_at` | `user_id`, `(user_id,start_at)` | Status CHECK; `duration_minutes > 0` |
| 5 | `appointment_services` | Service lines for a booking | `id`, `user_id`, `appointment_id`→appointments CASCADE, `service_id`→services, `service_name_snapshot`, `price`, `duration_minutes` | `appointment_id` | Snapshot protects history |
| 6 | `visits` | Performed service event (walk-in, check-in, quick sale) | `id`, `user_id`, `customer_id`, `appointment_id`, `is_quick_sale`, `visited_at`, `notes` | `user_id`, `(user_id,visited_at)`, `customer_id` | No soft delete |
| 7 | `visit_services` | Service lines for a visit | `id`, `user_id`, `visit_id`→visits CASCADE, `service_id`, snapshot, `quantity`, `unit_price`, `discount_amount`, `line_total`, `duration_minutes` | `visit_id` | Line total is stored, not generated |
| 8 | `payments` | Money received against a visit | `id`, `user_id`, `visit_id`→visits, `amount`, `method`, `paid_at`, `note` | `user_id`, `(user_id,paid_at)`, `visit_id` | `amount > 0`; methods cash/card/other |
| 9 | `expenses` | Business outgoings | `id`, `user_id`, `title`, `category`, `amount`, `spent_at`, `note` | `user_id`, `(user_id,spent_at)` | **Hard delete**; no `deleted_at` |
| 10 | `color_formulas` | Hair-color recipe | `id`, `user_id`, `title`, `brand`, `color_code`, `oxidant_type`, `oxidant_percent` REAL, `mix_ratio`, `processing_minutes`, `notes`, `customer_id`, `visit_id` | `user_id`, `customer_id` | No `deleted_at` |
| 11 | `color_formula_items` | Recipe lines | `id`, `user_id`, `formula_id`→formulas CASCADE, `product_name`, `color_code`, `amount` REAL, `unit` | `formula_id` | `amount > 0` |
| 12 | `customer_photos` | Before/after images | `id`, `user_id`, `customer_id`, `visit_id`, `storage_path`, `local_path`, `photo_type`, `caption`, `consent_given`, `deleted_at` | `user_id`, `customer_id`, `visit_id` | `local_path` is local-only |
| 13 | `sync_outbox` | Local change queue | `id`, `entity_type`, `entity_id`, `operation`, `payload` JSON, `created_at`, `attempt_count`, `last_error`, `status` | `status`, `(entity_type,entity_id)` | **No `updated_at`/`processed_at`** |
| — | `schema_migrations` | Applied versions | `version` PK, `name`, `applied_at` | — | Created by the runner |

**Foreign keys declared:** appointments→customers; appointment_services→appointments (CASCADE), →services; visits→customers/appointments; visit_services→visits (CASCADE), →services; payments→visits; formulas→customers/visits; items→formulas (CASCADE); photos→customers/visits.

**Foreign-key enforcement:** `PRAGMA foreign_keys = ON` appears only at line 7 of the migration. It is a **per-connection** setting and is never executed by `getDatabase()`. After the first launch, migrations are skipped, so the pragma is not applied at all. FK enforcement is therefore **off by default** (DB-02).

## 2. Cloud schema (PostgreSQL / Supabase) — 12 tables

Same entities; `UUID` primary keys defaulting to `uuid_generate_v4()`; `TIMESTAMPTZ`; `BIGINT` money; `BOOLEAN` flags; `NUMERIC(5,2)` / `NUMERIC(8,2)` for formula amounts.

All 12 tables have `ALTER TABLE … ENABLE ROW LEVEL SECURITY`, each with a single owner policy, e.g.:

```sql
CREATE POLICY "customers: owner only" ON public.customers
  USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id);
```

- 12 table policies + 4 storage policies = **16 policies**.
- `profiles` additionally has `handle_new_user()` + `on_auth_user_created` trigger, which inserts a profile row on signup (`001_initial_schema.sql:26-40`).
- An `update_updated_at()` trigger is attached to all 12 tables (`:267-289`).
- Storage: migration `001` creates the private `customer-photos` bucket idempotently (`ON CONFLICT (id) DO NOTHING`). Select/insert/delete policies live in `001`; the update policy is added by `003_photo_storage_policy.sql`.
- No `supabase/config.toml`; the files are meant to be pasted into the SQL editor.
- No `deleted_at` on `visits`, `visit_services`, `payments`, `expenses`, `color_formulas`, `color_formula_items`.

## 3. Local vs cloud differences

| Concern | SQLite | PostgreSQL | Impact |
|---|---|---|---|
| UUID generation | Client (`generateUUID`) | DB default `uuid_generate_v4()` | Fine if client always sends IDs |
| Timestamps | ISO text, app-managed | `timestamptz`, default `now()` + update trigger | Server overrides client `updated_at` on UPDATE (DB-12) |
| Money | `INTEGER` | `BIGINT` | Compatible |
| Flags | `INTEGER 0/1` + CHECK | `BOOLEAN` | Push/pull must convert |
| Formula decimals | `REAL` | `NUMERIC(5,2)` / `NUMERIC(8,2)` | Rounding drift (DB-09) |
| `customer_photos.local_path` | Present | Intentionally absent | Must be stripped before push |
| `profiles.id` | `TEXT PK`, set to `user_id` | `UUID PK REFERENCES auth.users` | Must match `auth.uid()`; any other value fails FK |
| `sync_outbox`, `schema_migrations` | Local-only | Absent | Correct |
| Soft delete | customers, appointments, photos | same | Consistent |
| Hard delete | expenses, visits, payments, formulas | same | Needs tombstones in outbox (DB-06) |
| Indexes | `customers(phone)`, `payments(visit_id)`, `visits(customer_id)`, `expenses(user_id)`, `color_formulas(user_id)`, photos indexes, outbox indexes | several missing | Performance only (DB-13) |
| `appointment_services` index | present | **absent** | Slow joins at scale |
| `payments.user_id` index | present | absent (only `(user_id, paid_at)`) | Covered by composite |

## 4. Relationships (both schemas)

```
auth.users 1 ── 1 profiles (id = user_id)

customers 1 ── N appointments
customers 1 ── N visits
customers 1 ── N color_formulas
customers 1 ── N customer_photos

appointments 1 ── N appointment_services
appointments 1 ── N visits            (optional link: check-in)

visits 1 ── N visit_services
visits 1 ── N payments
visits 1 ── N color_formulas
visits 1 ── N customer_photos

color_formulas 1 ── N color_formula_items

sync_outbox ── polymorphic (entity_type, entity_id)   [no FK by design]
```

Every table carries `user_id`, including child rows, so RLS and local filters are uniform. This is deliberate and correct for a single-tenant-per-owner app, at the cost of denormalisation.

**Missing link:** a visit is not guaranteed to belong to the same customer as its appointment; no trigger/check enforces cross-row consistency.

## 5. Migrations and versioning

| Aspect | Local | Cloud |
|---|---|---|
| Mechanism | `schema_migrations(version, name, applied_at)` + `runMigrations` | Raw SQL file, manual execution |
| Idempotent | Yes (`IF NOT EXISTS`, version check) | Yes — `IF NOT EXISTS` indexes/tables, policies dropped before recreation, bucket `ON CONFLICT DO NOTHING` (enforced by `supabase-migrations.test.ts`) |
| Transactional | `db.execute(sql)` per file; plugin executes statements; no explicit transaction | Supabase SQL editor runs as one batch; partial failure possible |
| Down migration | none | none |
| Checksums | none | none |
| Adding a migration | Must add `import … ?raw` + array entry in `migrations.ts` | Drop a new file; no CLI config present |
| Bucket provisioning | n/a | Created by `001` with `ON CONFLICT (id) DO NOTHING` |
| Types | hand-written interfaces | hand-written `database.types.ts` |

`runMigrations` is sound for the current single migration. The risk is future: a failed migration leaves `schema_migrations` without the row (good), but partially-created tables remain because DDL is not wrapped in a transaction.

## 6. RLS and Storage review

**Strengths**

- RLS enabled on every table; no table is accidentally public.
- Single, uniform predicate `auth.uid() = user_id`; `WITH CHECK` prevents moving rows to another owner.
- Storage paths are namespaced by `auth.uid()` and policies check `(storage.foldername(name))[1]`.
- `profiles` is protected by both RLS and a signup trigger.

**Weaknesses / risks**

| Risk | Detail | Severity |
|---|---|---|
| Never executed live | Key/URL preflight passes (`auth/v1/health` 200) but migrations are not applied (`PGRST205`); no DB credential yet. Probe has not run | High |
| No `TO authenticated` clause | Applies to `anon` too; `auth.uid()` is null so no rows — safe but relies on null semantics | Low |
| Policies not idempotent | Fixed in T16: every policy is preceded by `DROP POLICY IF EXISTS` (or a `duplicate_object` handler) | Resolved |
| Bucket absent | Fixed in T16: `001` creates the private bucket idempotently | Resolved |
| No UPDATE policy on storage | Fixed by `003_photo_storage_policy.sql` | Resolved |
| `profiles` insert already done by trigger | Client `createProfile` pushes an `insert`; server row exists → plain INSERT conflicts. Sync must use **upsert** | High for T09 |
| `updated_at` trigger | Server `now()` always wins; client timestamps are ignored on update, breaking last-write-wins | High for T10 |
| Child rows lack owner consistency checks | `appointment_services.user_id` could differ from parent; only RLS prevents reading, not insertion of mismatched rows | Medium |
| `payments.visit_id` referenced visits without a delete policy | Resolved by `002`: `ON DELETE CASCADE` (owned child); optional references use `SET NULL` | Resolved |

**Migration review (001–003, static):** all statements are re-runnable as written
(`IF NOT EXISTS`, policy drops, `CREATE OR REPLACE FUNCTION/TRIGGER`,
`duplicate_object` guard, bucket `ON CONFLICT`). `002` supplies the missing
`(user_id, updated_at)` pull indexes and explicit FK delete behaviour. Two
non-blocking notes: `002` relies on PostgreSQL's default constraint names
(correct after `001` on a fresh project), and `003` cannot update the UPDATE
policy definition if it ever changes — drop it first if that becomes necessary.

## 7. Encoding conventions

| Value | Encoding | Evidence | Verdict |
|---|---|---|---|
| Money | Integer Toman × 100 (`formatToman` divides by 100) | `helpers.ts:50-63`; migration comments `:4`; service test | Consistent, but the `amountCents` parameter name is misleading |
| Timestamps | ISO-8601 UTC (`Z`) | `nowISO()`; all inserts | Consistent |
| Local calendar day | Derived from `toISOString().slice(0,10)` | `jalali.ts:54-56` | **Wrong for non-UTC users** (DB-11) |
| Day range queries | `dateISO + 'T00:00:00.000Z' … 'T23:59:59.999Z'` | 4 repositories + calculator | Wrong boundaries for UTC+ offsets (DB-11) |
| Week | Monday-based, computed with `getWeekStart` | `jalali.ts:60-90` | Depends on UTC-parsed input dates |
| Currency | `IRR`, displayed as Toman | `profiles.currency_code` default | No conversion logic; display assumes Toman |
| Booleans | SQLite 0/1, PG boolean | schemas | Converted in sync layer (to be written) |
| Formula amounts | REAL / NUMERIC | schemas | Drift risk |
| Soft delete | `deleted_at` timestamp | 3 tables | Expenses/visits/payments/formulas cannot be tombstoned |

## 8. Database defects

| ID | Defect | Evidence | Impact | Fix owner |
|---|---|---|---|---|
| DB-01 | `sync_outbox` has no `updated_at`/`processed_at`, but `markOutboxDone` writes `updated_at` | `outbox.repository.ts:51` vs `001_initial.sql:203-214` | First successful push throws; no backoff scheduling | T03 — **resolved** 2026-11-13 (migration 002 + real columns) |
| DB-02 | `PRAGMA foreign_keys = ON` only inside the migration | `001_initial.sql:7`; no pragma in `database.ts` | FK enforcement off after first launch; orphan rows possible | T02 — **resolved** 2026-11-13 |
| DB-03 | Multi-table writes are not transactional | appointment/visit/repo code; no `beginTransaction` anywhere | Partial appointments, visits, sales | T03 — **resolved** 2026-11-13 (`withTransaction`) |
| DB-04 | No pull cursor / `sync_state` table | local schema | Incremental pull cannot be built without a new migration | T10 — **resolved** 2026-11-13 (migration 003, single-row cursor) |
| DB-05 | Child rows (`appointment_services`, `visit_services`, `color_formula_items`) are never enqueued | repositories | Cloud restore loses line items and therefore all money detail | T03 — **resolved for appointments/visits**; formulas in T11 |
| DB-06 | Expensive/visit/payment/formula hard deletes have no tombstone and no `deleted_at` server-side | schema | Deletions cannot be replayed on other devices | T03/T10 — **expense tombstone resolved** 2026-11-13 (local migration 004 + server migration 002); visit/payment/formula deletes arrive with their flows |
| DB-07 | `profiles.id` must equal `auth.uid()`, but the server already inserts the row via trigger; client pushes `insert` | `001_initial_schema.sql:27-40`; `profile.repository.ts:31-58` | First profile sync conflicts unless the push uses upsert | T09 — **resolved** 2026-11-13 (push always upserts by `id`) |
| DB-08 | Cloud migration is not idempotent; bucket creation is commented out | `001_initial_schema.sql` | Re-run fails; photos unusable until manual setup | T16 — **resolved** 2026-11-13 (indexes `IF NOT EXISTS`, policies dropped first, bucket `ON CONFLICT DO NOTHING`, enforced by a test) |
| DB-09 | `REAL` locally vs `NUMERIC(5,2)/(8,2)` remotely | schemas | Sub-gram rounding differences after round-trip | T11 — **resolved** 2026-11-13 (schema rounds to 2 decimals, caps at 999.99; see D-33) |
| DB-10 | No constraint/unique guard for overlapping appointments; `end_at > start_at` unchecked | appointments schema | Race can create overlaps; bad rows possible | T06 |
| DB-11 | Local-day semantics encoded as UTC calendar dates and UTC day bounds | `jalali.ts:54-56`, repositories | Wrong day totals for UTC+3:30 (BUG-05) | T04 |
| DB-12 | Server `updated_at` trigger overrides client timestamps | `001_initial_schema.sql:267-289` | Last-write-wins cannot use client clocks; sync conflict policy undefined | T10 — **resolved** 2026-11-13 (cursor uses the max server timestamp; pending local rows win) |
| DB-13 | Cloud indexes missing relative to local | both schemas | Slower pull/queries at scale | T10 — **resolved** 2026-11-13 (`002_sync_indexes_and_fk.sql` adds `(user_id, updated_at)` on all 12 tables) |
| DB-14 | `payments.visit_id` lacks `ON DELETE CASCADE`; other FKs lack `ON DELETE` policy | cloud schema | Future delete flows blocked or order-dependent | T10 — **resolved** 2026-11-13 (CASCADE for owned children, SET NULL for optional references) |
| DB-15 | No unique constraint on `(entity_type, entity_id, operation, created_at)` in outbox | outbox schema | Duplicate queue entries from retries/double-clicks | T03 |

## 9. Data integrity risks and required guards

| Risk | Scenario | Required guard |
|---|---|---|
| Orphan service lines | App killed between parent and child inserts | Transaction around parent + children + outbox (T03) |
| Lost money detail | Device wiped, only parent rows pushed | Enqueue child rows; parent payload must include or reference them (T03) |
| Duplicate appointments | Double tap / retry | Client idempotency key + disabled submit; optional unique guard (T06) |
| Overlapping bookings | Two devices create concurrently | Re-check inside transaction; document server-side policy (T06/T10) |
| Unreplayable deletes | Expense deleted offline on device A | Outbox tombstone with full row payload (T03) |
| Cross-owner leakage | Bug omits `user_id` filter | RLS as backstop + local repository tests for scoping (T01/T16) |
| Wrong daily totals | Query at 00:10 local | Single local-day helper; tests around midnight/DST (T04) |
| Profile duplication | Trigger + client insert both run | Upsert on `id`; `ensureProfile` idempotent (T05/T09) |
| Precision drift | Formula 12.345 g round-trips | Encode decimals as integers or align NUMERIC scale (T11) |
| Server timestamp override | Offline edit on device A, later sync | Conflict policy based on server `updated_at` + client op order (T10) |

## 10. Justified deviations (do not "fix" blindly)

| Deviation | Why it is acceptable |
|---|---|
| `profiles.id = user_id` duplication | Makes local joins and RLS uniform; server requires `id` to reference `auth.users` |
| `user_id` repeated on child tables | Enables uniform RLS and simple repository filters; storage cost is negligible |
| `local_path` only on device | Device file paths are meaningless on the server; sync must strip it |
| `sync_outbox` and `schema_migrations` local-only | They are device state, not user data |
| Stored `line_total` | Preserves historical amounts when prices/discounts change; must be recomputed only at creation |
| Snapshot columns on service lines | Required so editing a service does not rewrite history |
| Hard delete for expenses | Matches the product decision; requires tombstones, not a schema change |
