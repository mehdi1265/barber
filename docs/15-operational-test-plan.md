# ۱۵ — Test Plan عملیاتی Release Candidate

> همه ردیف‌ها تا زمان اجرای واقعی روی Staging، وضعیت **NOT RUN** دارند.
> پر کردن ستون Actual فقط با شاهد واقعی (log، اسکرین‌شات، خروجی SQL) مجاز است.
> هیچ ردیفی با «به‌نظر درست است» PASS نمی‌شود.

---

## ۰. پیش‌نیاز و قواعد اجرا

| مورد | مقدار |
|---|---|
| محیط | Staging تأییدشده طبق `docs/13-release-owner-approval.md` |
| حساب‌ها | `rls-a@…` و `rls-b@…` (Auto Confirmed) |
| کلاینت‌ها | دو دستگاه/دو پروفایل مستقل با دیتابیس محلی جدا |
| پیش‌نیاز | Migration ۰۰۱–۰۰۵ دو بار + `verify_release_schema.sql` سبز |
| ممنوع | هر تماس با Production، هر حساب واقعی، هر Migration اضافه |

قواعد داده تست:

- ردیف‌های probe با marker یکتا (`RLS <marker>`) ساخته می‌شوند.
- پاک‌سازی فقط با `id` + `user_id` و فقط برای همان اجرا.
- در صورت ابهام مالکیت: توقف و بررسی دستی؛ هیچ DELETE سراسری.
- شاهد هر ردیف در `supabase/tests/` یا ضمیمه گزارش ثبت شود.

## ۵. معیار PASS برای این Plan

یک ردیف PASS است اگر:

1. Actual با شاهد مشخص پر شده باشد.
2. Expected دقیقاً برقرار شده باشد.
3. هیچخطای جانبی (خطای console، ردیف باقی‌مانده، فایل سرگردان) مشاهده نشده باشد.

وضعیت کل Plan فقط وقتی `PASS` است که همه ردیف‌های الزامی (AUTH، RLS، SYNC-01…10، ST) اجرا و سبز شده باشند.
در غیر این صورت وضعیت همان `NOT RUN` یا `FAIL` باقی می‌ماند.
